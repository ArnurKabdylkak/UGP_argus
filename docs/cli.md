# UDPR — руководство оператора

Консольная утилита `udpr`: один статический бинарь без внешних зависимостей.
Заворачивает произвольный поток байт в протокол UDPR и доставляет его на
другую сторону канала. Формат кадров и правила протокола описаны в
[спецификации](protocol.md).

## Сборка

```bash
go build -o udpr ./cmd/udpr
```

Либо через `make`:

```bash
make build     # сборка
make test      # go test ./... -race
make selftest  # прогон канала с 20% потерь
make lint      # golangci-lint, если установлен
```

Бинарь не требует конфигурационных файлов и внешних библиотек: всё задаётся
флагами и переменными окружения.

## Команды

| Команда | Назначение |
|---|---|
| `send` | передать поток на другую сторону |
| `recv` | принять **один** поток и выйти |
| `serve` | постоянно принимать потоки, складывая их файлами в каталог |
| `selftest` | прогнать поток через себя с имитацией потерь и сверить SHA-256 |

Общая справка — `udpr help`. Все команды печатают служебные сообщения в
stderr: stdout может быть самим потоком данных.

Все команды останавливаются по SIGINT и SIGTERM: передача и приём
прерываются между пакетами, статистика печатается, код возврата — 1.

## `send` — передача

```
udpr send -host HOST [-port N] [-file PATH|-] [-mtu N] [-window N] [-rto D]
          [-lport N | -laddr ADDR] [-deadline D] [-loss F] [-v]
```

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `-host` | — | адрес получателя, **обязателен** |
| `-port` | 5555 | порт получателя |
| `-file` | `-` | файл с данными; `-` означает stdin |
| `-mtu` | 1372 | payload на пакет, байт (предел 1372) |
| `-window` | 32 | размер окна в пакетах (предел 32) |
| `-rto` | 250ms | **начальный** таймаут повтора; дальше выводится из измеренного RTT |
| `-min-rto` | 2ms | нижний предел адаптивного таймаута |
| `-max-rto` | 2s | верхний предел адаптивного таймаута |
| `-bitrate` | 0 | предел скорости отправки, Мбит/с (0 — без предела) |
| `-lport` | 0 | фиксированный локальный порт (0 — эфемерный) |
| `-laddr` | — | фиксированный локальный адрес, перекрывает `-lport` |
| `-deadline` | 0 | общий предел времени передачи (0 — без предела) |
| `-loss` | 0 | имитация потерь канала, 0…1 (для проверки повторов) |
| `-v` | false | отладочный лог |

Примеры:

```bash
# файл
udpr send -host 10.0.0.2 -port 5555 -file data.bin

# поток: архив каталога уходит без промежуточного файла
tar cz /var/log | udpr send -host 10.0.0.2 -port 5555

# фиксированный обратный канал и предел времени
udpr send -host 10.0.0.2 -lport 5556 -deadline 30m -file dump.sql
```

### Фиксация локального порта

По умолчанию ОС выдаёт отправителю эфемерный порт, и он меняется при каждом
запуске. Тогда обратный поток подтверждений каждый раз приходит на новый
порт, и описать его постоянным правилом межсетевого экрана невозможно —
пришлось бы открывать весь эфемерный диапазон.

`-lport` закрепляет порт, и обратный канал получает неизменный 5-tuple.
Отправитель печатает фактический адрес сокета — тот, на который придут
подтверждения:

```
[send] 10.0.0.1:5556 -> 10.0.0.2:5555, сессия 4eb9dfef
```

Если порт занят, запуск завершается понятной ошибкой, а не тихим переходом
на эфемерный.

### Вывод

```
[send] sent=729 retransmit=185 acks=564 bytes=1000000, время 3.75 c, итоговый RTO 12.4ms
[send] ACK Guard отклонил 12 пакетов (последний: превышен лимит частоты ACK)
```

`итоговый RTO` — до чего сошлась оценка времени оборота. Это лучший
индикатор качества канала: сравните его с `ping` до второй стороны.

| Счётчик | Значение |
|---|---|
| `sent` | отправлено уникальных DATA-пакетов |
| `retransmit` | повторных отправок |
| `acks` | принято корректных подтверждений |
| `bytes` | передано байт полезной нагрузки |

Строка про ACK Guard появляется, только если что-то было отклонено. Её
регулярное появление — повод проверить обратный канал: либо лимит частоты
занижен, либо в канал попадает посторонний трафик.

## `recv` — одноразовый приём

Принимает один поток и завершается по `FIN` или по тишине длиннее `-idle`.
Предназначен для отладки и разовых передач; для шлюза используйте `serve`.

```
udpr recv [-bind ADDR] [-port N] [-out PATH|-] [-window N] [-idle D] [-loss F] [-v]
```

| Флаг | По умолчанию | Env | Назначение |
|---|---|---|---|
| `-bind` | 0.0.0.0 | `UDPR_BIND` | адрес прослушивания |
| `-port` | 5555 | `UDPR_PORT` | порт прослушивания |
| `-out` | `-` | — | файл для данных; `-` означает stdout |
| `-window` | 32 | `UDPR_WINDOW` | окно приёма в пакетах (предел 32) |
| `-idle` | 10s | `UDPR_IDLE` | выход после тишины |
| `-loss` | 0 | — | имитация потерь обратного канала, 0…1 |
| `-v` | false | — | отладочный лог |

```bash
udpr recv -bind 0.0.0.0 -port 5555 -out received.bin

# в конвейер: распаковка на лету
udpr recv -port 5555 | tar xz -C /restore
```

Вывод — те же счётчики, что у приёма в составе `serve`:

```
[recv] received=729 dup=6 out_of_order=606 rejected=0 acks=686 bytes=1000000, время 3.75 c
```

| Счётчик | Значение |
|---|---|
| `received` | принято DATA-пакетов |
| `dup` | дубликатов (отправитель не увидел подтверждения) |
| `out_of_order` | пришло не на своё место, собрано буфером |
| `rejected` | отброшено: битые, чужие, вне окна |
| `acks` | отправлено подтверждений |
| `bytes` | принято байт полезной нагрузки |

Высокий `out_of_order` при нулевом `dup` — норма для канала с потерями:
буфер пересборки делает ровно то, ради чего он есть.

## `serve` — постоянный приём

Штатный режим шлюза. Слушает непрерывно, принимает сессии последовательно и
параллельно, переживает разрывы и перезапуск отправителей, каждый поток
кладёт отдельным файлом. Останавливается по SIGINT/SIGTERM.

```
udpr serve [-bind ADDR] [-port N] -dir PATH [-window N] [-idle D] [-max N] [-loss F] [-v]
```

| Флаг | По умолчанию | Env | Назначение |
|---|---|---|---|
| `-bind` | 0.0.0.0 | `UDPR_BIND` | адрес прослушивания |
| `-port` | 5555 | `UDPR_PORT` | порт прослушивания |
| `-dir` | — | `UDPR_DIR` | каталог для принятых потоков, **обязателен** |
| `-window` | 32 | `UDPR_WINDOW` | окно приёма в пакетах |
| `-idle` | 60s | `UDPR_IDLE` | выселение замолчавшей сессии |
| `-max` | 64 | `UDPR_MAX` | предел одновременных сессий |
| `-loss` | 0 | — | имитация потерь обратного канала |
| `-v` | false | — | отладочный лог |

Каталог создаётся, если его нет. Имя файла — `<timestamp>-<session>.bin`,
где `timestamp` — время начала сессии в UTC:

```
20260823T161836-4eb9dfef.bin
```

Каждая сессия открывает свой файл; данные пишутся через буфер и
сбрасываются на диск при закрытии сессии.

```bash
udpr serve -bind 0.0.0.0 -port 5555 -dir /var/lib/udpr/inbox
```

Вывод по завершении каждой сессии и по остановке:

```
[serve] сессия 4eb9dfef от 10.0.0.1:5556 -> 20260823T161836-4eb9dfef.bin
[serve] сессия 4eb9dfef от 10.0.0.1:5556 ЗАВЕРШЕНА: received=729 ... , длительность 3.8 c
[serve] остановлен, итоги: sessions=12 completed=11 evicted=1 rejected=3 bytes=8912345
```

**`ЗАВЕРШЕНА` против `ПРЕРВАНА`.** Первое означает, что поток передан
полностью и закрыт `FIN`. Второе — что сессия замолчала дольше `-idle` и
была выселена: часть данных потеряна. В итогах им соответствуют `completed`
и `evicted`. Ненулевой `evicted` — это инцидент, а не статистика.

## `selftest` — проверка

Поднимает приёмник и отправителя в одном процессе, прогоняет случайный поток
через канал с заданной долей потерь и сверяет SHA-256 исходных и принятых
данных. Второй узел не нужен.

```
udpr selftest [-size N] [-mtu N] [-window N] [-rto D] [-loss F] [-v]
```

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `-size` | 262144 | размер тестового потока, байт |
| `-mtu` | 1372 | payload на пакет |
| `-window` | 32 | размер окна |
| `-rto` | 100ms | таймаут повторной отправки |
| `-loss` | 0 | доля потерь канала, 0…1 |
| `-v` | false | отладочный лог |

```bash
udpr selftest -size 1000000 -loss 0.2
```

```
[selftest] 1000000/1000000 байт, потери канала 20%, целостность: OK
```

Нарушение целостности или недобор байт — код возврата 1.

## Коды возврата

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | отказ выполнения: недоставка, ошибка ввода-вывода, нарушенная целостность, остановка по сигналу |
| 2 | ошибка вызова: неизвестная команда, отсутствие аргументов |

Ошибки разбора флагов обрабатывает стандартный механизм `flag` и завершает
процесс с кодом 2.

Значения вне пределов формата отклоняются **до** открытия сокета:

```
$ udpr send -host 10.0.0.2 -mtu 9000
[udpr] ошибка: mtu=9000 вне диапазона 1..1372
```

Это осознанное поведение: канал настраивают под конкретное железо, и молча
подменять MTU или окно на «ближайшее допустимое» недопустимо — оператор
должен узнать о расхождении.

## Переменные окружения

Задают значения по умолчанию для флагов. Приоритет: явный флаг → переменная
окружения → встроенное умолчание.

| Переменная | Флаг | Команды |
|---|---|---|
| `UDPR_BIND` | `-bind` | `recv`, `serve` |
| `UDPR_PORT` | `-port` | `recv`, `serve` |
| `UDPR_DIR` | `-dir` | `serve` |
| `UDPR_WINDOW` | `-window` | `recv`, `serve` |
| `UDPR_IDLE` | `-idle` | `recv`, `serve` |
| `UDPR_MAX` | `-max` | `serve` |

Сработавшие переменные печатаются при старте, чтобы источник настройки не
был сюрпризом при разборе инцидента:

```
[recv] слушаю 127.0.0.1:5601 (из окружения: UDPR_IDLE, UDPR_PORT)
```

Некорректное значение переменной игнорируется в пользу встроенного
умолчания — переменная окружения не должна ронять демон при старте.

## Логи и статистика

Отчёты о ходе работы (строки `[send]`, `[recv]`, `[serve]`) идут в stderr
всегда. Служебный лог пишется через `log/slog` тоже в stderr.

| Уровень | Что попадает | Когда виден |
|---|---|---|
| `WARN` | выселение сессии по таймауту, ошибки сессий | всегда |
| `INFO` | открытие и закрытие сессий | с `-v` |
| `DEBUG` | повторные отправки, отклонённые подтверждения, битые пакеты | с `-v` |

Без `-v` уровень логирования — `WARN`: в обычном режиме демон молчит, пока
всё идёт штатно, а ход работы виден по строкам `[serve]`.

```
time=2026-08-23T16:18:36+05:00 level=INFO msg="новая сессия" component=server session=2199897443 peer=10.0.0.1:5556
time=2026-08-23T16:18:40+05:00 level=WARN msg="сессия выселена по таймауту (поток не завершён)" component=server session=2199897443 bytes=524288
```

Формат `key=value` разбирается стандартными сборщиками логов; для отправки в
SIEM достаточно перенаправить stderr.

### unit-файл systemd

```ini
[Unit]
Description=UDPR data-diode receiver
After=network-online.target

[Service]
Type=simple
Environment=UDPR_BIND=0.0.0.0
Environment=UDPR_PORT=5555
Environment=UDPR_DIR=/var/lib/udpr/inbox
Environment=UDPR_IDLE=60s
ExecStart=/usr/local/bin/udpr serve

RestartSec=2
StandardOutput=journal
StandardError=journal

# приёмнику не нужны ни привилегии, ни доступ куда-либо кроме своего каталога

StateDirectory=udpr
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes

[Install]
WantedBy=multi-user.target
```

### Правила межсетевого экрана

Прямой канал — одна пара портов, обратный — строго ответный поток. При
фиксированном `-lport` обе стороны описываются постоянным 5-tuple:

```
# на устройстве B: принимать данные только от A
udp src 10.0.0.1:5556 dst 10.0.0.2:5555  → allow

# обратный канал: только подтверждения A ← B
udp src 10.0.0.2:5555 dst 10.0.0.1:5556  → allow (и, при наличии, проверка размера: ровно 28 байт)
```

Пакет подтверждения всегда занимает ровно 28 байт и не содержит полезной
нагрузки, поэтому обратный поток проверяем по размеру на уровне
оборудования — см. [ACK Guard](protocol.md#ack-guard).

### Проверка целостности вручную

```bash
# сторона A
sha256sum data.bin
udpr send -host 10.0.0.2 -file data.bin

# сторона B
sha256sum /var/lib/udpr/inbox/20260823T161836-4eb9dfef.bin
```

## Настройка производительности

Потолок задаёт **частота подтверждений**, а не сокеты:

```
пропускная способность ≈ AckRate × AckEvery × MTU
```

Замеры на loopback, один поток, 200 МБ, `-rto 20ms`:

| Конфигурация | Время | Пропускная способность |
|---|---|---|
| подтверждение на каждый пакет, лимит 5000/с | 33,0 с | ~6 МБ/с |
| агрегированное подтверждение, лимит 20000/с | 1,1 с | ~180 МБ/с (≈1,5 Гбит/с) |

Практические рекомендации:

* **Канал с потерями** — вмешиваться обычно не нужно: таймаут повтора
  адаптивный, он сходится к реальному обороту за несколько подтверждений.
  `-rto` задаёт только стартовое значение, пока не снято первое измерение.
  Итоговый таймаут печатается в конце передачи — если он заметно больше
  ожидаемого RTT, смотрите на джиттер канала.
* **Отправитель обгоняет приёмник** (у принимающей стороны слабый процессор
  или медленный диск) — ограничьте выдачу: `-bitrate 400`. Вспышка на
  скорости процессора переполняет очередь сетевой карты и приёмный буфер,
  а потерянный так пакет стоит целого повтора.
* **Канал с большой задержкой** — упирается в окно из 32 пакетов
  (≈45 КБ в полёте). Это предел формата версии 1, флагами не обходится.
* **`-mtu`** имеет смысл уменьшать, если в тракте есть звено с меньшим MTU:
  фрагментированная датаграмма теряется целиком при потере любого фрагмента.
* **Прежде чем менять транспорт** — проверьте `AckRate`, `AckEvery` и `MTU`.
  Горячий путь протокола не аллоцирует память, узкое место не в нём.

## Диагностика

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `ошибка: mtu=... вне диапазона` | значение больше предела формата | привести к 1372 и меньше |
| `не удалось занять локальный порт` | `-lport` уже используется | освободить порт или сменить его |
| Передача висит, `retransmit` растёт, `acks=0` | обратный канал закрыт | проверить правило для потока B → A |
| `ACK Guard отклонил ... (чужой session_id)` | в обратный канал попадает посторонний трафик | проверить фильтрацию обратного потока |
| `ACK Guard отклонил ... (превышен лимит частоты ACK)` | приёмник подтверждает чаще расчётного | увеличить `AckEvery` на приёмнике либо лимит на отправителе |
| Сессия `ПРЕРВАНА`, `evicted` растёт | отправитель замолчал или потерян `FIN` | проверить связь и увеличить `-idle` |
| `rejected` растёт при нулевом `received` | чужая версия протокола, битый канал или посторонний трафик на порту | запустить с `-v` и посмотреть причину отбрасывания |
| Данные не совпали по SHA-256 | сессия прервана и файл неполный | сверить размер и статус сессии в логе |
| Высокий `dup` | подтверждения теряются на обратном пути | проверить обратный канал, уменьшить `AckDelay` |

Первый шаг при любом непонятном поведении — `-v`: он показывает причину
каждого отброшенного пакета и каждой повторной отправки.

Проверка самого бинаря без сети:

```bash
udpr selftest -size 1000000 -loss 0.2
```

Если целостность нарушена здесь, проблема не в канале.
